# Fork & Flower Designs

Marketing site and event inquiry platform for **Fork & Flower Designs**, a
floral-forward event-styling business serving New Jersey and surrounding
areas.

Built with Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS,
Framer Motion, Resend, and Cloudflare Turnstile. Designed for deployment
on Vercel.

## Getting started

```bash
npm install --legacy-peer-deps
npm run dev
```

Open <http://localhost:3000>.

## Scripts

| Command              | What it does                                            |
| -------------------- | ------------------------------------------------------- |
| `npm run dev`        | Dev server with Turbopack                               |
| `npm run dev:webpack`| Dev server with Webpack (fallback)                      |
| `npm run dev:clean`  | Clear caches, then start dev                            |
| `npm run build`      | Production build                                        |
| `npm run start`      | Start production server                                 |
| `npm run lint`       | ESLint                                                  |
| `npm run clean`      | Remove `.next` and `node_modules/.cache`                |
| `npm run email:dev`  | React Email preview server (see below)                  |

## Environment variables

Copy `.env.example` to `.env.local` and fill in the values. The example
file documents the resolution order, dev escape hatches, and the
Phase 1 (resend.dev sandbox) vs Phase 2 (verified domain) email setup.

Production deploys on Vercel require:

- `RESEND_API_KEY`, `FROM_EMAIL`, `BUSINESS_EMAIL`
- `TURNSTILE_SECRET_KEY`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`
- `NEXT_PUBLIC_SITE_URL`
- `SLACK_WEBHOOK_URL` (optional but recommended)

## Email templates

Inquiry-form emails (customer confirmation + owner notification) are
React Email templates in `src/emails/`, sent through Resend from
`src/lib/email.ts`.

### Preview locally

```bash
npm run email:dev
```

Opens the React Email preview UI at <http://localhost:3001> with both
templates listed. Sample data is provided by
`src/emails/data/sampleInquiry.ts` via `.PreviewProps` on each
template — edit either file and the preview hot-reloads.

The default preview uses the typed-name signature fallback. To preview
the drawn-PNG signature path, swap `sampleInquiryTyped` for
`sampleInquiryDrawn` in `NewInquiryNotificationEmail.tsx` and flip
`hasSignatureAttachment` to `true`.

### Test real sends in development

1. Set `RESEND_API_KEY` and `FROM_EMAIL` in `.env.local` (see
   `.env.example` for full notes on the resend.dev sandbox).
2. Set `NEXT_PUBLIC_SITE_URL=http://localhost:3000` for local routes,
   then set `NEXT_PUBLIC_EMAIL_ASSET_BASE_URL` to a publicly-routable
   URL (e.g. a Vercel preview deploy or an ngrok tunnel) so the email
   logos and Instagram icon are loadable by Gmail's image proxy.
   Without this, embedded images will appear broken because Gmail
   cannot fetch `http://localhost`.
3. Set `BUSINESS_EMAIL` to the inbox that owns your Resend account.
4. (Optional) `FORCE_CLIENT_CONFIRMATION=true` to also send the
   customer email locally — only works if the form's email field
   matches your Resend account owner; Resend rejects any other
   recipient while `FROM_EMAIL` is on resend.dev.
5. `npm run dev`, submit the inquiry form at
   <http://localhost:3000/inquiry>, and watch your inbox.

### Email assets

Brand images served to email clients live in `public/email/`:

| File                | Purpose                                          |
| ------------------- | ------------------------------------------------ |
| `logo-on-light.png` | Header logo (cream banner)                       |
| `logo-on-dark.png`  | Footer logo (charcoal banner)                    |

The Instagram icon is generated by
`scripts/generate-instagram-icon.mjs`. Re-run it (`node scripts/generate-instagram-icon.mjs`)
only if the brand color or icon shape changes.

## Deploy on Vercel

The site is configured for Vercel out of the box (`vercel.json` sets the
install command to `npm install --legacy-peer-deps` because React 19 has
strict peer-dep ranges some libraries have not caught up to). After
configuring the env vars above, deploys are zero-config.
